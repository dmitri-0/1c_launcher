# 1C Launcher - Лончер баз 1С

GUI-лончер для управления базами данных 1С с поддержкой дерева папок, недавних баз, горячих клавиш и раздельных учетных данных для разных режимов работы.

## Особенности

- 📁 **Дерево папок**: Организация баз в древовидной структуре с неограниченной вложенностью
- ⏱️ **Недавние базы**: Автоматическое отслеживание последних запущенных баз с сортировкой по времени
- ⌨️ **Горячие клавиши**: Быстрый доступ ко всем функциям (включая инструменты разработчика)
- 🔐 **Раздельные учетные данные**: Отдельные логины/пароли для режима Предприятие, Конфигуратор и Хранилища
- 🔧 **Настройка баз**: Редактирование параметров подключения, папок, версий, учетных данных
- 📋 **Копирование баз**: Создание дубликатов баз с новым ID
- ➕ **Добавление баз**: Создание новых записей прямо из интерфейса
- 🗑️ **Удаление баз**: Удаление баз из списка с очисткой кэша
- 🧹 **Очистка кэша**: Удаление программного и пользовательского кэша конкретной базы
- 🔄 **Чтение ibases.v8i**: Совместимость со стандартным файлом списка баз 1С
- 📋 **Копирование строки подключения**: Быстрое копирование Connect-строки в буфер обмена
- 🧰 **Инструменты разработчика**: Запуск инструментов ИР, консоли сервера 1С, операций UpdateDBCfg/DumpCfg

## Установка

```bash
# Клонирование репозитория
git clone https://github.com/dmitri-0/1c_launcher.git
cd 1c_launcher

# Установка зависимостей
pip install -r requirements.txt

# Запуск
python main_tree_gui.py
```

## Горячие клавиши

### Глобальная для вызова окна:
- **Alt+D** — активирует окно лаунчера с любого рабочего окна Windows.
  Во время ожидания закрытия процесса (после **Del**) работает как **аварийный сброс**:
  прерывает ожидание и не трогает процесс — если вы передумали закрывать 1С.

    - Комбинация настраивается во внешнем файле `src/launcher.toml` (`[hotkey]`) и читается
      динамически — после сборки файл лежит рядом с exe (`dist\launcher.toml`), правка кода/пересборка не нужна:
      ```toml
      [hotkey]
      modifiers = 'Alt'   # 'Alt', 'Ctrl', 'Shift', 'Win' через '+', либо число (1|2|4|8)
      vk = 0x44           # виртуальный код клавиши: 0x44 = D, 0x31 = 1, 0x70 = F1 и т.д.
      ```

## Настройки (внешний файл)

Все настройки лаунчера вынесены во внешний файл **`launcher.toml`** (стандарт TOML) и
читаются динамически при каждом запуске — менять их можно **без пересборки**:

- **в исходниках:** `src/launcher.toml`;
- **в сборке:** `launcher.toml` лежит **рядом с exe** (`dist\launcher.toml`) — сборщик
  (`buildexe` в `navigator.ps1`) копирует его автоматически после PyInstaller.

Что настраивается: пути (ibases.v8i, CF-дампы, логи, инструменты ИР, DBM API),
глобальная горячая клавиша (`[hotkey]`) и список отслеживаемых приложений
(`[[tracked_applications]]`).

Если файла нет или он повреждён — используются встроенные значения по умолчанию
(те же, что были зашиты в `src/config.py`), приложение продолжает работать.

## Основные функции

### Запуск баз данных
- **Enter** - чистый запуск Предприятия (без отладки) с использованием учетных данных для Предприятия
- **F3** - запуск в режиме Предприятие с подключением к отладке (`/debug -attach`) с использованием учетных данных для Предприятия
- **F4** - запуск Конфигуратора с использованием учетных данных для Конфигуратора
- Автоматическое определение исполняемого файла 1С на основе версии и разрядности

### Инструменты разработчика
- **F5** - запуск инструментов ИР (режим `IR_TOOLS`, если он включен в конфигурации)
- **F6** - запуск консоли сервера 1С
- **F7 / Ctrl+F7 / F8** - операции для обслуживания конфигурации (UpdateDBCfg / обновление из репозитория / DumpCfg)

### Управление учетными данными
В диалоге настроек базы (Ctrl+E) доступна таблица с тремя типами учетных данных:
- **Предприятие** - используется при запуске через Enter / F3
- **Конфигуратор** - используется при запуске через F4
- **Хранилище** - для подключения к хранилищу конфигурации

Для обратной совместимости сохранены старые поля Usr/Pwd, которые используются как fallback.

### Публикация базы на Apache (F9 / Shift+F9)

Действие "Опубликовать" публикует выбранную базу на веб-сервере Apache через `webinst.exe`:

- **webinst.exe** берётся той же версии платформы, что и база (поле `Version`),
  из `C:\Program Files\1cv8\{Version}\bin\webinst.exe` (или `Program Files (x86)` для x86).
- **Экземпляр Apache** выбирается по версии платформы базы. Это решает ошибку
  `409 Conflict` ("Различаются версии клиента и сервера"): один Apache может
  загрузить только одну версию модуля `wsap24.dll`, поэтому для разных версий
  платформы нужны разные экземпляры Apache (разные порты/конфиги).

Список экземпляров Apache задаётся в JSON-файле `%APPDATA%\1c_launcher\web_publish.json` — **без хардкода в коде**; если файла нет, используется один универсальный инстанс (`C:\Apache24`, порт 80, любая версия):

```json
{
  "apache_instances": [
    {"name": "apache-80", "apache_root": "C:/Apache24", "port": 80, "versions": ["8.3.25.1394"]},
    {"name": "apache24-8327", "apache_root": "C:/Apache24-8327", "port": 81, "versions": ["8.3.27.1688"]}
  ],
  "default_host": "127.0.0.1"
}
```

Дополнительные поля экземпляра: `template_root` (откуда копировать, если
каталога нет), `service_name` (имя службы Windows, по умолчанию
`Apache24-<порт>`), `apache_bits` (32/64, по умолчанию определяется по
`httpd.exe`).

**Авто-настройка:** если каталог экземпляра Apache ещё не существует, F9
сам скопирует его из шаблона (первый настроенный экземпляр или поле
`template_root`) и поправит конфиги: заменит пути источника на новые
(`Define SRVROOT` и т.п.), переключит `Listen` на порт экземпляра,
закомментирует старую строку `LoadModule _1cws_module`, создаст каталог
`logs` и **удалит старые блоки публикаций 1С** из скопированного
`httpd.conf` (новый Apache обслуживает только то, что публикуют в НЕГО).
webinst при публикации допишет модуль нужной версии платформы.

**Запуск Apache «штатно» (автоматически):** после F9 лаунчер сам поднимает
Apache. Если он запущен **от имени администратора** — консольный процесс на
порту останавливается (если был), **служба Windows устанавливается
автоматически** (`httpd.exe -k install`, включается автозапуск `start= auto`)
и стартует; если прав администратора нет — выводится предупреждение и Apache
запускается скрытым процессом (без окна, но без автозапуска после
перезагрузки).

**Проверка после публикации:** после успешной публикации лаунчер проверяет,
что Apache слушает порт экземпляра, и делает HTTP GET по URL публикации
(с логином/паролем из настроек базы). В сообщении будет
«✅ Публикация отвечает: http://…» либо подсказка, что проверить
(«Управление Apache», F2).

### Снапшоты DBM API: обновить копии

Меню «Действия» → **«Снапшоты: обновить копии…»** показывает, какие базы
лаунчера «пора обновить»: у них появился **более новый снапшот** DBM API
(логика «голубых» строк из DBM API — у базы данных есть снапшот с бОльшим
сроком истечения, чем у текущего), а в имени базы **нет даты** (то есть она
ещё не обновлялась).

Диалог показывает **полный список баз из раздела «Мои снапшоты»** DBM API
(все базы лаунчера, чей `Ref` совпадает со снапшотом пользователя) — открывается
по меню **«Действия» → «Снапшоты: обновить копии…»** или **Ctrl+U**. Колонки:
База 1С | Снапшот | Строка соединения | Истекает (текущий) | Истекает (новый).
Если для базы можно обновиться (в DBM API есть
более новый снапшот — «голубая» строка, и в имени базы нет даты) — показывается
кнопка **«Обновить копию»**.

Кнопка делает следующее:
1. если в DBM API **уже есть свободный** более новый снапшот (не занят другой
   базой лаунчера) — берёт его `connection string` сразу;
2. иначе — открывает **мастер создания снапшота DBM API** (последовательно:
   БД → снапшот-мастер → ERP-сервер → описание; БД, мастер и сервер
   **предзаполнены**: сервер выбирается ближайший к `Srvr=` из строки
   соединения базы, чтобы меньше переключать); после отправки задачи
   открывается **модальное окно ожидания — как в DBM API**: описание задачи,
   таблица параметров (Task ID), **живой лог выполнения** (обновляется при
   каждом опросе), progress bar (indeterminate, по завершении — 100%),
   статус «Готово! Снапшот создан.», кнопка «Отмена». Статус задачи
   опрашивается таймером в фоновом потоке — GUI не блокируется. По завершении
   берётся connection string нового снапшота
   (номер `…_2`, `…_3` DBM присваивает независимо от сервера);
3. создаёт копию базы с датой в имени и подставляет строку подключения —
   то же самое, что F12, но без ручного ввода; после успеха показывается
   **окно с результатом** (имя созданной копии и новая строка подключения).

«Обновить все» выполняет строки **последовательно** (каждая полностью: мастер →
ожидание → F12 → результат), переходя к следующей только после завершения
предыдущей; обновлённые строки больше не предлагаются.

Меню **«Действия» → «Очистить „Недавние“ от копий с датой…»** — одним действием
убирает из «Недавних» все копии, в имени которых есть дата `<дата>` (как Del
по каждой, но с одним подтверждением; базы не удаляются, только снимается
пометка «недавняя» и возвращается исходная папка).

**Enter** в поле «Описание» мастера создаёт снапшот, если мастер и сервер
выбраны (иначе — ничего). **Enter** на строке таблицы «Обновить копии»
запускает обновление строки, если для неё доступна кнопка (иначе — ничего).

Галочка **«Скрыть копии с датой в имени (<дата>)»** (по умолчанию включена)
прячет датированные копии; сняв её, видно все базы раздела — и у датированных
копий на голубом снапшоте тоже есть кнопка «Обновить копию». Обновление
всегда каскадное (как F12): к имени дописывается новая дата, состояние на
старом снапшоте сохраняется.

Несколько «ХРАН»-баз могут ссылаться на один снапшот поколения — каждая
получает свою строку. Если баз, привязанных к снапшотам, нет — диалог
предлагает создать новый снапшот через DBM API.

**«Создать новый снапшот…»** (в диалоге) и меню **«Действия» → «Создать
снапшот DBM API…»** — мастер создания снапшота **только через механизм DBM
API** (как в самом DBM API, последовательно): выбор БД DBM API → выбор
снапшота-мастера (имя) → выбор ERP-сервера → описание (авто) → создание
через `POST /api/v1/snapshots`.

**Токен DBM API запрашивается раз в час** (кэш TTL 3600 с; запрос выполняет
хелпер на venv DBM API — там же расшифровка учётных данных). Если токен
получить нельзя — подсказка «запустите DBM API (F11) и авторизуйтесь».

### Управление Apache (F2)

Меню «Действия» → «Управление Apache…» (F2) показывает таблицу всех
настроенных экземпляров: порт, версии платформы, **состояние службы
Windows** (`running`/`stopped`/`absent`), слушается ли порт, и **какие базы
публикуются в этот экземпляр** (по версии платформы — «необходимость исходя
из публикаций»). Экземпляры, которые нужны по публикациям, но не запущены,
подсвечиваются в сводке сверху.

Кнопки: **Запустить**, **Остановить**, **Перезапустить**, **Установить
службу** (требуют прав администратора) и **Обновить**. Если лаунчер
запущен **без прав администратора**, кнопки управления службами
недоступны (с подсказкой) и в диалоге показывается предупреждение —
запустите лаунчер от имени администратора; просмотр статусов работает и
без прав.

В **заголовке окна** лаунчера отображается режим запуска:
`Базы 1С [администратор]` — если процесс под админом, иначе просто
`Базы 1С`.

**Настройки базы (Ctrl+E):** поля «Публикация (имя)» и «Публикация
(каталог)» сохраняются в ibases.v8i как `PublishName` / `PublishDir`
(например `shop` и `c:\1CWEB\shop`). Если каталог задан — публикация
пишется туда (webinst кладёт туда `default.vrd`), иначе — в
`htdocs\<wsdir>`. В диалоге также виден **порт публикации** для выбранной
версии платформы (например «apache24-8327 — порт 81»).

**Разрядность:** модуль расширения веб-сервера (wsap24.dll) должен
совпадать по разрядности с Apache. Разрядность Apache определяется по
`httpd.exe` (PE-заголовок); если установлена платформа не той разрядности
(например, Apache 64-битный, а платформа 32-битная) — публикация не
запускается и пользователю выводится понятное сообщение.

**Права администратора:** публикация (F9) и отмена публикации (Shift+F9)
**требуют запуска лаунчера от имени администратора** — без прав действие
блокируется с подсказкой (webinst пишет в `conf/httpd.conf` и каталог
публикации, Apache работает как служба Windows). Диалог «Управление Apache»
(F2) доступен и без админа (только просмотр/запуск/остановка служб;
«Установить службу» — только под админом).

**default.vrd:** webinst перезаписывает `default.vrd` в каталоге
публикации — это штатно и правильно: webinst подключается к базе
(`-connstr`) и генерирует свежий vrd из конфигурации, поэтому веб-сервисы
и точки (например `arm_inspector`) в нём всегда актуальны. Каждая база
пишет свой vrd в свой каталог (`c:\1CWEB\shop\default.vrd`,
`c:\1CWEB\zup\default.vrd`, …).

Путь к `wsap24.dll` в `httpd.conf` `webinst.exe` прописывает сам — из каталога
своей установки, поэтому конфиги разных Apache не конфликтуют.

Вся логика вынесена в отдельный модуль `src/services/web_publisher.py`
(без GUI-зависимостей, покрыт тестами).

### Копирование базы (Ctrl+D)

При копировании базы:
- Создаётся новая база с новым UUID
- Сохраняются все параметры исходной базы (имя, строка подключения, папка, учетные данные и т.д.)
- К имени исходной базы автоматически добавляется текущая дата (например: `АСТОР ТЕСТ 2025-11-20`)
- Копируются все три пары учетных данных (Предприятие, Конфигуратор, Хранилище)

### Добавление новой базы (Shift+F10)

- Создание новой записи с уникальным ID
- Новая база добавляется в папку, на которой стоит курсор
- Открывается диалог настроек для заполнения параметров

### Удаление базы (Del)

При удалении базы:
- Если база в папке "Недавние" - убирается флаг IsRecent, база возвращается в исходную папку
- Если обычная база - удаляется из списка с очисткой кэша
- Очищается программный кэш: `%LOCALAPPDATA%\1C\1cv8\{ID}`
- Очищается пользовательский кэш: `%APPDATA%\1C\1Cv82\{ID}`

> **Внимание**: Удаление из списка НЕ удаляет файлы базы данных!

### Очистка кэша (Shift+Del)

Очищает кэш выбранной базы без удаления её из списка:
- Программный кэш (AppData\Local\1C\1cv8\{ID})
- Пользовательский кэш (AppData\Roaming\1C\1Cv82\{ID})

## Недавние базы

Папка "Недавние" - это служебная папка скрипта, которая:
- Автоматически отображает базы с флагом `IsRecent=1`
- Сортирует базы по времени последнего запуска (самые свежие первыми)
- Всегда раскрыта при запуске программы
- Курсор автоматически устанавливается на последнюю запущенную базу

При запуске базы (Enter, F3 или F4):
- База автоматически помечается как недавняя
- Сохраняется её исходная папка в поле `OriginalFolder` (не сохраняется в файл)
- Обновляется время последнего запуска `LastRunTime`
- База перемещается в начало списка недавних

## Формат файла ibases.v8i

```ini
[База Производство]
ID=a1b2c3d4-e5f6-7890-abcd-ef1234567890
Connect=Srvr="production-server:1541";Ref="ProductionDB";
Folder=/Рабочие
IsRecent=1
LastRunTime=2025-11-20T14:30:00.000000
App=Auto
Version=8.3.24.1353
AppArch=x86_64
OrderInTree=100.0
Usr=Пользователь
Pwd=
UsrEnterprise=БухгалтерИванов
PwdEnterprise=pass123
UsrConfigurator=АдминистраторСистемы
PwdConfigurator=admin456
UsrStorage=РазработчикПетров
PwdStorage=dev789
StoragePath=tcp://storage-server:1542/config-storage
```

### Описание полей:

**Основные поля:**
- `ID` - уникальный идентификатор базы (UUID)
- `Connect` - строка подключения к базе
- `Folder` - папка для организации баз в дереве (например: `/Тестовые/Подпапка`)
- `IsRecent` - флаг недавней базы (1 или отсутствует)
- `LastRunTime` - время последнего запуска в формате ISO 8601

**Настройки платформы:**
- `App` - путь к исполняемому файлу 1С (Auto для автоопределения)
- `Version` - версия платформы (например: 8.3.23.2040)
- `AppArch` - разрядность (x86 или x86_64)
- `OrderInTree` - порядок в дереве (число)

**Учетные данные (старый формат, для обратной совместимости):**
- `Usr` - имя пользователя
- `Pwd` - пароль

**Учетные данные (новый формат):**
- `UsrEnterprise`, `PwdEnterprise` - для режима Предприятие
- `UsrConfigurator`, `PwdConfigurator` - для Конфигуратора
- `UsrStorage`, `PwdStorage` - для Хранилища конфигурации
- `StoragePath` - путь к хранилищу

**Параметры публикации (F9):**
- `PublishName` - псевдоним публикации (wsdir), например `shop`
- `PublishDir` - каталог публикации, например `c:\1CWEB\shop`

**Служебные поля (не сохраняются в файл):**
- `OriginalFolder` - исходная папка недавней базы (только в памяти)

## Запуск 1С

Программа автоматически определяет путь к исполняемому файлу 1С:
1. Если указан `App` в настройках базы - использует его
2. Иначе ищет по версии и разрядности в стандартных путях:
   - `C:\Program Files\1cv8\{Version}\bin\1cv8.exe` (x86_64)
   - `C:\Program Files (x86)\1cv8\{Version}\bin\1cv8.exe` (x86)
3. Если не найдено - использует `1cestart.exe` из `common`

Запуск осуществляется через временный BAT-файл с автоматическим удалением после запуска.
